# Editando este README

Quando estiver pronto para personalizar este README, edite-o e utilize o modelo abaixo (sinta-se à vontade para estruturá-lo como preferir). Agradecimentos ao [makeareadme.com](https://www.makeareadme.com/) por este modelo.

## Sugestões para um bom README

Cada projeto é diferente, portanto avalie quais seções se aplicam ao seu. As seções usadas neste modelo são sugestões para a maioria dos projetos open source. Embora um README possa ser extenso, é melhor pecar pelo excesso do que pela falta de informação. Se achar que o README está muito grande, considere usar outra forma de documentação em vez de remover informações.

## Nome
Escolha um nome autoexplicativo para seu projeto.

## Descrição
Informe o que seu projeto faz especificamente. Forneça contexto e adicione links para referências que o visitante possa desconhecer. Uma lista de funcionalidades ou uma seção de contexto podem ser incluídas aqui. Se houver alternativas ao seu projeto, destaque os diferenciais.

## Badges
Alguns READMEs exibem pequenas imagens com metadados, como o status dos testes. Utilize o Shields para adicionar alguns ao seu README. Muitos serviços também possuem instruções para adicionar badges.

## Visuais
Dependendo do que você está construindo, pode ser interessante incluir capturas de tela ou vídeos (frequentemente em GIF). Ferramentas como ttygif ajudam, mas confira o Asciinema para uma abordagem mais completa.

## Instalação
Dentro de cada ecossistema pode haver uma forma comum de instalação, como Yarn, NuGet ou Homebrew. Considere que quem está lendo pode ser um iniciante e precisar de orientações detalhadas. Listar passos específicos reduz ambiguidades e acelera o uso do projeto. Caso funcione apenas em um contexto específico ou possua dependências manuais, inclua uma seção de requisitos.

## Uso
Mostre exemplos generosamente e, se possível, o resultado esperado. Inclua o menor exemplo de uso que puder demonstrar e forneça links para exemplos mais complexos se forem muito longos para o README.

## Suporte
Informe onde as pessoas podem buscar ajuda: issue tracker, sala de bate-papo, e-mail etc.

## Roadmap
Se houver planos para futuras versões, liste-os aqui.

## Contribuição
Diga se está aberto a contribuições e quais são os requisitos para aceitá-las. Se possível, descreva como o contribuinte pode começar, incluindo scripts ou variáveis de ambiente necessárias. Essas informações também serão úteis para você mesmo no futuro. Documente comandos de lint ou testes para garantir qualidade e reduzir problemas.

## Autores e agradecimentos
Mostre sua gratidão a quem contribuiu para o projeto.

## Licença
Para projetos open source, informe o tipo de licença.

## Status do projeto
Se o desenvolvimento diminuiu ou parou, avise logo no início do README. Assim, outra pessoa pode assumir a manutenção e permitir que o projeto continue.
